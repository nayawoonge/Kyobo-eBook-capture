# PageCapture

macOS에서 책 화면의 선택 영역을 연속 캡처하고 PNG와 PDF로 저장하는 작은 Swift 앱입니다. macOS 14 이상, 외부 패키지 없이 Apple 기본 프레임워크만 사용합니다.

## 실행

1. `PageCapture.app`을 더블클릭합니다.
2. 앱의 **화면 기록 권한**, **손쉬운 사용 권한** 버튼으로 시스템 설정을 열고 **PageCapture**를 허용합니다. macOS가 재실행을 요청하면 앱을 종료했다가 다시 여세요. 자동으로 권한을 변경하지 않습니다.
3. 교보eBook 앱에서 책을 한 페이지 보기로 열고, PageCapture의 대상 앱 목록에서 교보 앱을 선택합니다.
4. **본문 영역 선택**을 누르면 도구 창이 잠시 숨겨지고 책 화면 위에 어두운 선택 화면과 안내 문구가 나타납니다. 본문의 왼쪽 위에서 오른쪽 아래로 마우스를 누른 채 드래그한 뒤 놓으세요. 주황색 테두리 안쪽이 저장되고 도구 창이 돌아옵니다. Esc는 취소입니다. 한 디스플레이 안에서 영역을 선택하세요.
5. 넘김 방법을 고릅니다. 기본값은 오른쪽 방향키입니다. 앱이 방향키를 받지 않으면 **넘김 위치 지정**을 눌러 다음 페이지 버튼을 클릭하세요.
6. **한 장 시험**을 눌러 저장된 화면과 PDF를 확인합니다. 이 기능은 페이지를 넘기지 않습니다.
7. 원하는 시작 페이지로 이동한 뒤 **캡처 장수**와 **넘긴 뒤 대기 시간**을 설정하고 **캡처 시작**을 누릅니다. 기본값은 3장 / 1.5초입니다. 현재 화면을 첫 장으로 저장합니다.
8. 종료 후 **결과 폴더 열기**에서 `book.pdf`를 열어 확인하고 AirDrop 또는 iCloud Drive로 옮겨 Goodnotes에서 가져옵니다.

캡처 중 **Esc**를 누르면 중지하고, 이미 저장한 페이지까지 PDF로 마무리합니다. 다른 앱으로 전환해도 중단됩니다. 마지막 캡처 뒤에는 페이지를 넘기지 않습니다.

## 권한을 켰는데도 인식되지 않을 때

버전 1.1에서는 **권한 상태 확인** 버튼으로 현재 실행 중인 앱이 인식한 권한을 확인할 수 있습니다. 상태 확인과 캡처 시작은 시스템 권한 팝업을 자동으로 띄우지 않습니다. 시스템 권한 요청은 **화면 기록 권한** 또는 **손쉬운 사용 권한** 버튼을 직접 누를 때만 합니다. **한 장 시험**에는 화면 기록 권한만 필요합니다. 손쉬운 사용이 꺼져 있으면 전역 Esc 중지는 사용할 수 없으며, 다른 앱으로 전환해 시작 전 캡처를 중단할 수 있습니다.

앱 수정 후 macOS에 이전 빌드의 권한 항목이 남아 있으면 설정에서 켜져 보여도 현재 앱은 권한이 없을 수 있습니다.

1. PageCapture를 `Cmd+Q`로 완전히 종료합니다.
2. 시스템 설정 → 개인정보 보호 및 보안 → 화면 및 시스템 오디오 녹음에서 **PageCapture만** 선택해 `−`로 제거합니다.
3. `+`를 눌러 현재의 `/Volumes/SSD_1TB/src/KyoboCapture/PageCapture.app`을 다시 추가하고 스위치를 켭니다. 파일 선택창에서 `Cmd+Shift+G`로 경로를 입력할 수 있습니다.
4. 손쉬운 사용 권한도 인식되지 않으면 개인정보 보호 및 보안 → 손쉬운 사용에서 PageCapture만 같은 방법으로 다시 등록합니다.
5. 앱을 다시 열고 **권한 상태 확인**을 누릅니다. 모두 허용됨이면 영역을 다시 선택해 시험합니다.

이 앱은 권한 데이터베이스를 수정하거나 다른 앱의 권한을 초기화하지 않습니다. 재등록은 사용자가 시스템 설정에서 직접 수행합니다.

## 저장 결과

기본 저장 위치는 앱 옆의 `Captures` 폴더입니다. 저장 폴더는 UI에서 변경할 수 있습니다. 실행마다 날짜와 고유 번호로 새 하위 폴더를 생성하므로 이전 작업을 덮어쓰지 않습니다.

```text
Captures/capture-날짜-고유번호/
  0001.png
  0002.png
  ...
  book.pdf
  session.json
```

- PNG는 디스플레이 배율을 반영해 저장하고, PDF에는 원래 비율로 넣습니다.
- 중지 또는 캡처 오류가 발생하면 저장된 페이지까지 PDF로 마무리합니다. 저장 장수와 종료 이유는 `session.json`에 남습니다.
- 같은 이미지가 나오면 대기 후 두 번 더 확인합니다. 계속 같으면 중복 페이지를 추가하지 않고 중단합니다. 이때 넘김 입력을 추가로 보내지 않습니다.
- 이미지가 조금이라도 달라지면 중복 검출이 안 될 수 있습니다. 반대로 연속된 빈 페이지처럼 완전히 같은 페이지는 중복으로 판단합니다. 결과 순서는 확인하세요.
- 앱이 강제 종료되어 PDF가 완성되지 않았으면 **이미지 폴더 → PDF**로 남은 PNG를 합칠 수 있습니다. 숫자 파일명 순으로 결합합니다.
- PDF는 이미지 기반입니다. 이 버전에는 OCR, 텍스트 선택, 목차 생성 기능이 없습니다.

## 캡처 품질

창 크기, 글자 크기, 위치, 디스플레이 배율을 고정하세요. 자동 잠금이나 화면 잠자기 상태에서는 캡처할 수 없습니다. EPUB의 표시 화면 수는 인쇄 책의 쪽수와 다를 수 있습니다. 첫 실행은 3장 정도로 시험하고, 화면 전환이 느리면 대기 시간을 늘리세요.

이 도구는 운영체제의 일반 화면 캡처와 입력 API를 사용합니다. 교보 앱 버전에 따라 자동 키 입력 또는 클릭을 받지 않을 수 있으므로 실제 앱에서 시험이 필요합니다. 화면 기록과 손쉬운 사용 권한은 사용자가 직접 허용해야 합니다. 파일과 화면은 외부 서버로 전송하지 않습니다.

## 소스와 빌드

`Sources/CaptureCore.swift`: PNG/PDF 저장, 캡처 순서, 중복 검출, 중단 처리.

`Sources/Selection.swift`: 디스플레이별 드래그 영역과 클릭 위치 선택.

`Sources/main.swift`: AppKit 화면, ScreenCaptureKit 캡처, CGEvent 페이지 넘김.

`Sources/SelfTests.swift`: 사용자 화면을 캡처하지 않는 합성 이미지 테스트.

빌드에는 Apple Command Line Tools의 Swift 컴파일러가 필요합니다. 이미 빌드된 앱 실행에는 추가 설치가 필요 없습니다. 앱은 빌드한 맥의 CPU 아키텍처에 맞게 생성됩니다.

```sh
cd /KyoboCapture
./build.command
./PageCapture.app/Contents/MacOS/PageCapture --self-test ./tests/output
```

기본 빌드 결과에는 로컬 ad-hoc 코드 서명을 사용합니다. 이 서명은 소스를 바꿔 빌드할 때 앱 식별값이 바뀌므로 권한 재등록이 필요할 수 있습니다. 변경이 없는 재빌드는 건너뛰어 기존 서명을 유지합니다. 이미 보유한 Apple Development 또는 Developer ID Application 서명 인증서를 사용하려면 `PAGECAPTURE_SIGNING_IDENTITY` 환경 변수에 해당 인증서 이름이나 식별자를 지정해 빌드할 수 있습니다. 빌드 스크립트는 인증서를 만들거나 시스템의 인증서 신뢰 설정을 바꾸지 않습니다.

참고: [Apple DTS의 ad-hoc 서명과 화면 기록 권한 설명](https://developer.apple.com/forums/thread/819406).

테스트는 페이지 수/순서, 마지막 페이지의 불필요한 넘김 방지, 취소 시 PDF 보존, 중복 화면 재시도, 느린 화면 전환, 포커스 이탈 시 입력 중단, 기존 PDF 덮어쓰기 방지, 이미지 폴더 재결합, 좌표 변환을 확인합니다. 실제 교보eBook에서의 화면 캡처·키 입력 호환성은 자동 테스트에 포함되지 않습니다.
